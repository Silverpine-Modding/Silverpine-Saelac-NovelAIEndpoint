# Live Xialong roleplay probe

This opt-in test makes real NovelAI requests and uses account allowance. It is not run by the ordinary offline dialogue tests or plugin build.

After promotion into plugin 1.2.14, the default mode tests the current production policy. Both `*-ab` modes are historical comparisons against a frozen 1.2.13 turn cue, labelled `baseline-1.2.13`; they do not apply an experimental overlay twice to the newly installed policy. Shared compatibility instructions still come from current `Plugin.cs`. The historical generation-boundary candidate retains its original fixed Elian/Mira example; production uses a neutral example with actual participant names.

Run the project with one argument: the Silverpine workspace directory. It reads the existing encrypted NovelAI credential only to authenticate to the fixed NovelAI text host. It does not print or save credentials, modify configuration, install a plugin, or load game saves.

Eight synthetic Silverpine-style scenarios are sent sequentially, with one second after each completion and at most one empty-response retry per scenario (16 calls maximum). There are no actor/formatting quality checks or retries. API/network errors stop the run. Full synthetic messages, responses and cleanup results are saved under the workspace's `artifacts/NovelAI-Roleplay-Probe-*` folder.

Supply a second argument, `reinforced`, to test the seven non-emotion scenarios with an older, stricter experimental presence/history/formatting overlay (14 calls maximum). That overlay forbids reactions allowed by the current production policy; it is retained for historical comparisons only and does not change the installed plugin. Current emotion cleanup is applied before local stops; raw output remains available for review.

Supply `speaker-anchor-ab` instead to compare the current prompt against a test-only combined candidate: explicit `Speaking NPC` / `Silent participants` labels plus an instruction and positive example returning narration focus to the active NPC before speech resumes. This runs the three group scenarios three times per arm, with alternating/interleaved arm order: 18 independent samples (36 calls maximum only if every sample needs an empty-response retry). Sampling, scenario context and cleanup remain the same. No seed is controlled. Review speaker ownership in raw and returned text separately, valid action enclosure, whether participant actions are merely reactive, and copying of the example. This is an exploratory test, not an installed plugin update.

Supply `generation-boundary-ab` to test the revised candidate against the current installed prompt using the same 18-sample plan. This candidate preserves unrelated turn/formatting guidance, replaces the roster wording with other participants who are not speakers for the generated turn, and adds the proposed text-generation-boundary reminder and simple example. It does not use the earlier `Silent participants` label or physical re-anchoring instruction. It explicitly excludes other participants' quoted replies from narration and says not to act out enforcing these generation rules within the story. Review the same issues as above, including in-world silencing/interruption, narration viewpoint and player control.

Compatibility instructions are extracted from current `Plugin.cs`; the test compiles current `DialogueTurnPolicy.cs`, `DialogueTextCleanup.cs` and `EmotionMetadata.cs`. Each scenario supplies a conversation roster: Elian alone, or Elian and Mira for the group cases. Request shape follows the plugin's streaming chat path, using temperature 0.7, top-k 64, top-p 0.95 and a 512-token output ceiling. It does not exercise Unity, the game's complete prompt-building pipeline, text-completion fallback, live request concurrency, or save persistence. Review absent-participant inventions and any other NPC's speech manually. Only the active NPC may speak; other listed conversation NPCs may only make brief nonverbal reactions enclosed in paired single asterisks.
